The customer app must preserve the illustrated premium visual system while retaining the later production capabilities reconciled from the POS/production lineage: Supabase Auth OTP/recovery and Google sign-in, R2/catalog cutover, product images, canonical vehicle/fitment selection, multi-vehicle garage context, customer-safe real sales-ranked popular parts, resilient catalog/EPC reads, commerce/cart/checkout/payments, orders/returns, delivery tracking, wishlist/compare/reviews, addresses, loyalty/service kits, and support chat.

## Release prohibitions
Production customer builds must not contain fake/demo RPC transports, seeded demo accounts/orders/tracking, fake contact details, helper/placeholder screens presented as features, retired Supabase project URLs, or dead menu controls.

Every customer APK/AAB must pass `python3 scripts/project_truth_guard.py release-check --app customer-android` and the Customer Android Canonical CI workflow before promotion.
