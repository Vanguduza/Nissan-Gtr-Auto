# Live Supabase + Cloudflare R2 Catalog Serving

## Locked runtime contract

Normal catalog browsing never requires downloading the complete encrypted Nissan catalog bundle.

### Customer app / website

1. Vehicle selector reads the published `catalog_v2` customer vehicle master from Supabase.
2. The selected canonical `vehicle_master_id` is sent to `catalog-live-r2`.
3. The gateway resolves the current immutable release in Supabase.
4. It reads only the selected vehicle's compact `vehicle_search` / `vehicle_fitment` shard from Cloudflare R2.
5. EPC part identities are joined to live `stock_items`, saleable stock and pricing in Supabase.
6. Customer UI receives friendly product data plus `VERIFIED_FIT`, never raw EPC browsing UI.

No full EPC file is downloaded to the browser or Android device.

### Staff / management EPC

1. Staff opens `/staff/catalog`.
2. Family → variant → section → diagram hierarchy comes from staff-authorized `catalog_v2` RPCs in Supabase.
3. Selecting a diagram asks `catalog-live-r2` for that diagram only.
4. The gateway reads the corresponding `diagram_parts` shard from R2.
5. The diagram image is returned as a short-lived signed R2 URL.
6. Staff can inspect PNC/OEM/applicability records and the actual diagram without downloading the catalog bundle.

The full encrypted bundle remains an optional offline/admin/disaster-recovery artifact only.

## R2 serving layout

Generated by `data-pipeline/scripts/build_r2_serving_indexes.mjs`:

```text
serving/nissan/<release>/
  vehicle/<hash>.ndjson.gz       # registered as vehicle_search + vehicle_fitment
  section-parts/<hash>.ndjson.gz # staff section technical rows
  diagram-parts/<hash>.ndjson.gz # staff diagram technical rows
```

Existing diagram images remain under the current R2 diagram prefix and are registered as
`object_kind=diagram_image`, keyed by the `catalog_v2` diagram id.

Supabase table `catalog_r2_serving_objects` is only a compact routing manifest. It does not duplicate
the EPC part corpus.

## Publication sequence

1. Build/normalize Nissan EPC release.
2. Publish complete customer vehicle master.
3. Run `build_r2_serving_indexes.mjs` over normalized part applicability NDJSON.
4. Upload generated `objects/` to the configured R2 bucket.
5. Run `register_r2_serving_manifest.mjs`.
6. Upload diagrams and run `publish_catalog_v2_diagram_index.mjs` to register diagram-id → R2 object mappings.
7. Validate `catalog-live-r2/health` reports serving objects and `full_catalog_download_required=false`.
8. Only then mark the release ready for verified customer fitment and full staff EPC browsing.

## Fail-closed rules

- Missing vehicle shard: do not infer fitment from visual artwork or model similarity.
- Missing/partial fitment shard: `FITMENT_UNRESOLVED`, never `VERIFIED_FIT`.
- Missing diagram mapping: staff sees catalog-republish-required state; do not fall back to unrelated diagrams.
- Customer surfaces never render OEM, PNC, diagram identifiers or EPC navigation.
- Staff EPC is technical/reference UI and remains role-protected.
